# patterns.html UXレビュー(パネル方式)

**実施日**: 2026-09-28
**対象**: `patterns.html`(時間帯パターン: 平日/休日)
**方式**: UXデザイナー3人(情報設計/データビジュアライゼーション/行動・信頼設計)+ PdM3人(グロース/データプロダクト/リーン・スコープ管理)、計6ペルソナによる3ラウンドの議論

## 経緯

「UXデザイナーとしてレビューして」という依頼に対し、単独のセルフレビューで回答したところ「本当にそれがUXデザイナーの視点か」と2度指摘を受けた。実際、最初の回答はエンジニアリング上の品質チェック(SVGのテキスト縮小バグなど)が中心で、UXデザイナーが本来最初に見るべき視点(ユーザーのゴール・メンタルモデル・情報階層・信頼設計)からのレビューになっていなかった。これを受けて、異なる専門性を持つ6人のペルソナを立て、3ラウンドの議論を行った。このプロセス自体は `panel-review` スキルとして汎用化した。

## P0 — 時期・スコープに関わらず今すぐ直すべき

### 1. 下部5枚の折れ線グラフが役割を無視した指標で描画されている(実バグ)
`patterns.html` 325-328行目付近の集計が、全ポート一律で `bikes_available` のみを平日/休日バケットに積んでいる。一方、上部の「いつからダメになるか」チャートの `metricFor()`(248行目)は正しく役割ごとに指標を切り替えている(office_district/near_station → `docks_available`、residential_origin → `bikes_available`)。結果、6本木ヒルズ・麻布台ヒルズ・アパホテル六本木駅東・六本木ファーストビルの**5ポート中4ポートで、本来ユーザーが気にすべき「満車で返せるか」が一切可視化されていない**。
**発見**: UX1(情報設計) / **全員一致でP0**。

## P1 — 方向性は合意、ただしサンプル数の閾値に応じて出し方を変える

### 2. onsetセクション(「いつからダメになるか」)のフェーズゲート化
平日データが閾値(暫定・平日10日を目安、統計的根拠はまだ無く要調整)に達するまでは、各ポート行を1行テキストサマリー+収集進捗表示に留め、閾値到達後に現行のドット可視化へ切り替える。
- 初期実装は自動切替でなく手動フラグ切替でよい(過剰実装回避)— PdM2
- 切替が無音で起きるとユーザーに説明できないため、収集進捗表示(例: 平日n/10日)と連動させる — UX1, UX3
- 閾値未満の1行テキストの文言はネガティブフレーミング(「まだ足りません」)を避け、「収集中: 平日n/10日」のような中立〜前向きな表現にする — UX3, PdM2
**発見**: PdM2 → PdM3が当初案(1行テキストへの永久格下げ)を撤回して合流。UX1, UX2, UX3, PdM1も同意。

### 3. 信頼度(サンプル数n)の視覚エンコーディング
- `.onset-dot` および折れ線グラフのマーカーに、nに応じたサイズ/不透明度の変化を実装する(閾値未満は小さく・低彩度の「暫定」スタイル、閾値到達後に現行の実線色へ「昇格」)
- `.onset-range-line`(2〜3点をつなぐ範囲線)は削除、または点線化して統計的信頼区間に見えないようにする
- n数は現状ホバー(title属性)専用で、タッチデバイスでは実質見えない。常時表示のインラインテキストにする
- 「昇格」の瞬間(暫定→確信色)が視覚的に唐突になる可能性があるため、実装後に一度確認する — UX3の留保
**発見**: UX2(dataviz)の"range-line削除+critical色単色使用をやめ、その分をn明示に振り替える"というゼロサム提案が着地点。UX3, PdM2, PdM3が賛同。

## P2 — 低コストで今すぐ足してよい

### 4. footerの文言を進捗表示に置換
「サンプル数が少ないうちは参考程度に見てください」という後ろ向きの免責文を、「平日 ${wdCount}/10日」のような収集進捗表示に置き換える。上記P1-2の1行テキスト版とも文言を揃える。
**発見**: PdM1, PdM2, PdM3, UX3が合意。

### 5. 最終更新日時の表示
meta-bar付近に最終更新日時を追加(実装コスト最小)。
**発見**: PdM1提案、全員賛成。

### 6. seijo.htmlへの相互リンク
`back-link` 付近に「今の空き状況を見る →」等でseijo.html(習慣化済みの日常利用PWA)への導線を追加。既存の高頻度接点をこのページの再訪動機として活用する。
**発見**: PdM1提案、全員賛成。ただしPdM1が当初求めたTL;DR・前回差分は**時期尚早として撤回**(n=2-3での断定を避けるため)。将来閾値到達時にTL;DR表示を有効化する条件分岐は、今回のP0/P1実装と同じコミットで先に仕込んでおく(先送りにしない)。

### 7. 見出し階層の整理
h1/subtitleが「いつからダメになるか」セクションの目的を代表しておらず、下部の折れ線グラフ群にも見出しが無い。各セクションに簡潔な見出しを追加する。
**発見**: UX1、特に反論なし。

### 8. 未使用コードの整理
未使用CSS(`.crosshair`)、使われていない3書体構成・`data-theme`切替機構(切替UIが存在しない)など、過剰な拡張性への投資を削る。
**発見**: PdM3、特に反論なし。

## 保持された対立(無理に解消していません)

**下部5枚グラフのY軸スケール統一は、P0かP1か**
- UX2: 「サンプル数の多寡と無関係に、今この瞬間から誤読を生んでいる実装ミス。データが増えてもmaxVal個別計算のままなら誤読は解消しない。P0のmetric修正と同じコミットで直すべき」
- PdM2: 「閾値到達後にn数エンコードと合わせて実装するP1の投資」

この点は今回のパネルで合意に至らず、実装判断は開発者(ユーザー)に委ねる。

## 最終推奨アクション(実装順)

1. **(P0)** 下部5枚グラフの集計を `metricFor(role)` に統一する
2. **(P1)** onsetセクションと下部グラフをサンプル数閾値でフェーズゲート化し、n連動の視覚エンコーディング(サイズ/不透明度)を実装。range-lineの削除/弱化
3. **(P2)** footer文言を収集進捗表示に置換、最終更新日時とseijo.htmlへの導線を追加、見出しと未使用コードを整理
4. スケール統一(P0説 vs P1説の対立点)は開発者判断で実施タイミングを決める
